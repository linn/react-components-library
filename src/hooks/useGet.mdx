# useGet

A hook that handles HTTP GET requests to a REST API endpoint, managing loading state, error handling, and the response result. Supports optional OIDC bearer token authentication (the signed-in user's token, from react-oidc-context's `AuthProvider` or a [`RequestAuthProvider`](?path=/docs/hooks-requestauthprovider--docs)) and flexible URL construction.

With `requiresAuth` it sends as the signed-in user and reports `hasToken` (so a page can wait for the token); it keeps only the latest answer and reports a rejected token (`tokenRejected`, with `signInAgain` for the page to call): see [Signed-in requests](?path=/docs/hooks-signed-in-requests--docs), which also describes what `send` returns.

## Signature

```js
const { send, isLoading, errorMessage, result, clearData, hasToken, status, apiMessage, tokenRejected, signInAgain } = useGet(url, requiresAuth);
```

## Basic usage

```jsx
import useGet from '@linn-it/linn-form-components-library/hooks/useGet';

function ProductDetail({ productId }) {
    const { send, isLoading, errorMessage, result } = useGet('/api/products');

    useEffect(() => {
        send(productId);
    }, [productId]);

    if (isLoading) return <p>Loading…</p>;
    if (errorMessage) return <p style={{ color: 'red' }}>Error: {errorMessage}</p>;
    if (!result) return null;

    return <h1>{result.name}</h1>;
}
```

## With a query string

```jsx
const { send, result } = useGet('/api/products');

// Fetches GET /api/products?category=widgets
send(undefined, '?category=widgets');
```

## With authenticated endpoints

```jsx
const { send, result } = useGet(
    '/api/secure/orders',
    true // requiresAuth — adds the signed-in user's Bearer token
);
```

## Clearing state

Use `clearData` to reset `result` back to `null` — for example when navigating to a different record:

```jsx
const { send, result, clearData } = useGet('/api/items');

const handleSelect = id => {
    clearData();
    send(id);
};
```

## Overlapping requests

Only the latest `send`'s answer is kept: if an earlier request answers after a newer one, its result, error and loading state are ignored. `clearData` also drops an answer still on its way. For waiting for the token, signing in again and safe error messages, see [Signed-in requests](?path=/docs/hooks-signed-in-requests--docs).
